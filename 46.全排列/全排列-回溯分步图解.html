全排列：回溯那棵树
到底是怎么长出来的

题目：给定一个不含重复数字的数组 nums，返回它所有的全排列。你的写法是标准的 used 数组 + path 回溯。核心就一句话：每层选一个没用过的数，递归下去，回来时把它撤销。下面把每一次递归、每一次撤销都画成步骤，建议直接点自动播放。

class Solution {
    List<List<Integer>> res = new ArrayList<>();
    public List<List<Integer>> permute(int[] nums) {
        int n = nums.length;
        boolean[] used = new boolean[n];
        List<Integer> path = new ArrayList<>();

        backtracking(nums,used,path);
        return res;
    }
    public void backtracking(int[] nums,boolean[] used,List<Integer> path){
        if(path.size() == nums.length){
            res.add(new ArrayList<>(path));
            return;
        }
        for(int i = 0;i< nums.length;i++){
            if(used[i] == true){
                continue;
            }
            used[i] = true;
            path.add(nums[i]);
            backtracking(nums,used,path);
            used[i] = false;
            path.remove(path.size()-1);

        }
    }
}

看图抓三个点

  • 树的层数 = 已选元素个数；到第 n 层就是叶子，得到一个完整排列。
  • 每个节点的分支 = 当前还没用过的数，used 为 true 的分支根本不会长出来。
  • 回溯 = 沿边退回去：先撤销标记、再从 path 移除，父节点于是能继续试下一个分支。
复杂度：叶子共 n! 个，每个叶子拷贝长度为 n 的 path，时间 O(n × n!)；递归栈与 path 占 O(n) 辅助空间，结果集本身占 O(n × n!)（不算辅助空间）。
为什么必须撤销：path 和 used 是全程复用的同一个对象，不撤销就会污染兄弟分支——比如选 1 的分支走完后不把 1 释放，选 2、选 3 的分支就永远用不到 1。「递归前做选择、递归后撤销」是所有排列/子集回溯题的固定骨架。
易错点：收集时写 res.add(path) 是错的，必须 new ArrayList<>(path) 拷贝一份，否则后续回溯修改的是同一个对象，最终结果全是空或重复。
