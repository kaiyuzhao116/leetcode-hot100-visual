全排列 II：有重复元素时
哪些分支根本不能走

题目：给定一个可能含重复数字的序列，返回所有不重复的全排列。你的写法先 Arrays.sort 排序，再用两个检查跳过：used[i] 已在路径里、同层跟前一个值相同且前一个没用。下面把每个位置能不能选、为什么不能逐个标出来，建议直接点自动播放。

class Solution {
    List<List<Integer>> res = new ArrayList<>();
    public List<List<Integer>> permuteUnique(int[] nums) {
        int n = nums.length;
        boolean[] used = new boolean[n];
        Arrays.sort(nums);
        List<Integer> path = new ArrayList<>();

        backtracking(nums,used,path);
        return res;

    }
    public void backtracking(int[] nums,boolean[] used,List<Integer> path){
        if(path.size() == nums.length){
            res.add(new ArrayList<>(path));
            return;
        }
        for(int i = 0;i< nums.length;i++){
            if(used[i] == true){
                continue;
            }
            if(i>0 && used[i-1] == false && nums[i] == nums[i-1]){
                continue;
            }
            used[i] = true;
            path.add(nums[i]);
            backtracking(nums,used,path);
            used[i] = false;
            path.remove(path.size()-1);

        }
    }
}

看图抓三个点

  • 红色 used：该位置已在当前路径，不能再选。
  • 橙色重复：同值且前一个同位置没被用，是会产生重复的分支，必须跳过。
  • 绿色可选：两个检查都通过，才真正做选择、递归下去。
复杂度：设去重后排列数为 U（U ≤ n!），每个叶子拷贝长度 n 的 path，时间 O(n × U)；排序 O(n log n)，递归栈与 path 占 O(n) 辅助空间。
为什么先排序：排序后相同数字一定相邻，才能用 nums[i] == nums[i-1] 判断重复；同层里让相同值的第一个（此时 used[i-1] 已被占用或在更深层）走、后面的跳过，就保证同一个值序列只生成一次。

used[i-1] 为什么要判断 false

排序后两个相同数字相邻，这个条件用来区分它们是同一层的平行选择（重复，要拦）还是不同层的上下关系（合法，要放行）。以 [1,1,2] 为例：

情况一 · 同层：used[0] = false → 跳过

        ∅
      /     \
   i=0      i=1      两个都是 1，平行候选
   (1)       (1)

i=0 走完已撤销、used[0] 变回 false；再选 i=1 走出来的排列一模一样，continue 跳过。

情况二 · 不同层：used[0] = true → 放行

       ∅
       |
      i=0      已选，used[0]=true
       |
      i=1      拼出 [1,1]，是新一层

前一个 1 是当前路径上的祖先，used[0] 为 true，条件不成立，不能跳过，放行。

  1. 先处理 i=0：used[0]=true，深入走完所有以这个 1 开头的排列，回来撤销，used[0] 变回 false。
  2. 轮到 i=1（值也是 1）：检查 used[0]——是 false 说明它没在路径里、那条分支已经处理过，现在选 i=1 等于把同一条路再走一遍，重复 → 跳过。
  3. 注意：不是因为它「还选着」才跳过，恰恰是因为它「已经走完、空出来」了。false=空闲=同层重复（拦）；true=占用=我祖先、不同层（放行）。
